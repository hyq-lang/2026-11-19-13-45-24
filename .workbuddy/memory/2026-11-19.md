## 重要 bug 修复 — Reveal 显现机制不可靠

- 用户反馈"为什么没变/还是这样"：截图显示 About 区只有人物图，右侧介绍/联系方式/数据卡全空白（opacity:0）。根因不是缓存，是 IntersectionObserver 没触发（threshold 0.12 + rootMargin -60px 下部分元素卡在 is-visible=false）。
- 教训：之前截图脚本强制 `.reveal{opacity:1}` 掩盖了这个 bug，导致误判为缓存问题。**验证 reveal 相关的显示问题必须看真实滚动状态，不要强制显现**。
- 修复：`src/components/Reveal.tsx` 从 IntersectionObserver 改为基于 scroll/resize/load + `getBoundingClientRect()` 检测（rect.top < vh-40 && rect.bottom>0 即加 is-visible），监听立即执行一次 check。已加 is-visible 则跳过。
- 验证：诊断脚本模拟逐屏滚动到底，检查全部 22 个 reveal 元素的 is-visible class，结果 TOTAL=22 VISIBLE=22 MISSING=0。诊断文件用完删除。build 通过。
- 注意：headless 虚拟时间下 CSS transition 不推进，诊断 opacity 会读到 0（假象），应检查 is-visible class 而非 computed opacity。
- **二次修复（根治）**：用户仍反馈右侧/数据卡空白。放弃依赖 JS 显现检测，改为默认可见方案：
  - `src/index.css` `.reveal` 默认 `opacity:1; transform:none`，is-visible 时播放 `@keyframes revealIn`（0→1）纯 CSS 动画。JS 检测失效也不影响可见性。
  - `index.html` 加原生兜底 script：load 后 1.2s + 全局 3s 强制给所有 .reveal 加 is-visible（不依赖 React/HMR）。
  - 顺带修正 index.html meta/title 的占位名「陈奕」→「洪英琦」。
  - 验证：不强制显现、仅滚动到 about 截图，右侧介绍/联系方式/4 数据卡全部可见。build 通过。
- **教训**：在此预览环境中 JS 显现检测（IO 或 scroll）可能整体不运行；关键内容必须默认可见，动画只做增强，绝不能让内容依赖 JS 才显示。
